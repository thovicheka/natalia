## Steps

Steps 1–4 are 🧑 and run **in your own terminal, in one shell session** (steps 3–4 share a shell variable). Don't run them through the agent (e.g. Claude Code's `!` prefix): that puts their output in the agent's chat. Nothing below prints the password. About 5 minutes.

### 1. 🧑 Install PostgreSQL 16 and pgvector
```bash
sudo apt update
sudo apt install -y postgresql postgresql-16-pgvector
```
*What it does:* installs PostgreSQL 16 and pgvector from Ubuntu 24.04's archive, and creates and starts the `16/main` cluster.

### 2. 🧑 Install the memory settings and restart
```bash
sudo install -m 644 -o postgres -g postgres \
  ~/projects/natalia/deploy/postgresql/natalia.conf /etc/postgresql/16/main/conf.d/natalia.conf
sudo systemctl restart postgresql
```
*What it does:* Ubuntu's `postgresql.conf` reads `conf.d/` last, so `natalia.conf` overrides the defaults:

| Setting | Value | Default | Why |
|---|---|---|---|
| `listen_addresses` | `localhost` | `localhost` | localhost only; set so it can't drift |
| `max_connections` | 20 | 100 | the flow, the bot, the website and a psql session; each connection is a process of ~5–10 MB |
| `shared_buffers` | 64MB | 128MB | the data is tens of MB in year one; the OS page cache does the rest |
| `work_mem` | 4MB | 4MB | fine for this data |
| `maintenance_work_mem` | 64MB | 64MB | used by the HNSW index build and VACUUM |
| `effective_cache_size` | 512MB | 4GB | planner hint only, allocates nothing |
| `jit` | off | on | JIT loads LLVM (tens of MB per backend) for big analytic queries Natalia doesn't run |
| `autovacuum_max_workers` | 2 | 3 | a handful of tables |

> **Adapting:** with 8 GB of RAM or more and nothing else on the box, keep PostgreSQL's defaults for `shared_buffers` and `max_connections`. Keep `jit = off` either way.

### 3. 🧑 Create the role and the database
```bash
NATALIA_DB_PW="$(openssl rand -hex 24)"     # 48 hex characters, safe in a URL; nothing printed
printf "CREATE ROLE natalia LOGIN PASSWORD '%s';\n" "$NATALIA_DB_PW" | sudo -u postgres psql -q -v ON_ERROR_STOP=1
sudo -u postgres createdb --owner=natalia --encoding=UTF8 --template=template0 natalia
sudo -u postgres psql -d natalia -c 'CREATE EXTENSION IF NOT EXISTS vector;'
```
*What it does:* a login role with a random password (sent to `psql` on stdin, so it never shows in the process list); a UTF-8 database owned by it (UTF-8 is needed for Khmer); and pgvector enabled in it. pgvector isn't a "trusted" extension, so a superuser must create it; the migration only checks it's there.

> **If** `CREATE ROLE` fails, generate a new password (first line) before retrying: PostgreSQL writes a failed statement, password included, to its log.

`pg_hba.conf` needs no change: Ubuntu's default already allows password (`scram-sha-256`) logins from `127.0.0.1`.

### 4. 🧑 Put `DATABASE_URL` in `.env`
```bash
sed -i '/^DATABASE_URL=/d' ~/projects/natalia/.env       # remove the fake line from .env.example
printf 'DATABASE_URL=postgresql://natalia:%s@127.0.0.1:5432/natalia\n' "$NATALIA_DB_PW" >> ~/projects/natalia/.env
unset NATALIA_DB_PW                                       # forget the password in this shell
```
*What it does:* `printf` is a shell builtin, so the password never appears on screen or in the process list.

Check the settings took effect:
```bash
sudo -u postgres psql -Atc "SELECT name, setting FROM pg_settings WHERE name IN ('shared_buffers','max_connections','jit','listen_addresses') ORDER BY name"
```
Expected: `jit|off`, `listen_addresses|localhost`, `max_connections|20`, `shared_buffers|8192` (8192 × 8 kB = 64 MB).

### 5. 🤖 The schema and the migration runner
Python side, in the project's `.venv` only:
```bash
uv add 'psycopg[binary]' python-dotenv
```
*What it does:* `psycopg[binary]` brings its own libpq, so no system `libpq-dev` is needed; `python-dotenv` lets `natalia/db.py` read `DATABASE_URL` from `.env` (the environment wins if set; the URL is never printed).

The schema is `migrations/0001_initial_schema.sql`:

| Table | What it holds |
|---|---|
| `sources` | one row per feed in `config/sources.yaml`, unique by feed URL |
| `articles` | one row per story: unique canonical `url`, `title`, `title_norm` (indexed, for de-duplication), `excerpt`, `body` (NULL when only the excerpt is allowed), `language`, `topics topic[]`, `published_at` |
| `embeddings` | `vector(384)` per article (the local model's size), with an HNSW cosine index |
| `summaries` | AI summary + "why it matters", one per article and language |
| `digests`, `digest_items` | one digest per day and language (with request and token counts), and its articles per topic, in order |

Domains `topic` (the 9 topics) and `lang` (`en`, `km`) reject anything else. Topics are a list per article ([why](decisions.md#topics-a-list-per-article-over-one-topic-column)).

`natalia/db.py` applies each pending `NNNN_*.sql` file in its own transaction, records it in `schema_migrations`, and holds an advisory lock so two runs can't migrate at once:
```bash
uv run python -m natalia.db status
uv run python -m natalia.db migrate
```

> **If you see** `cannot connect: connection failed: connection to server at "127.0.0.1", port 5432 failed: Connection refused`, **it means** PostgreSQL isn't installed or isn't running. Do steps 1–2, then `systemctl status postgresql@16-main`. (The message names host and port only, never the password.)

### 7. Measure PostgreSQL's memory
```bash
systemctl status postgresql@16-main --no-pager | grep Memory
systemctl show postgresql@16-main -p MemoryCurrent -p MemoryPeak
```
*What it does:* reads the cluster's cgroup memory, the true figure. Adding up the processes' RSS counts the shared buffers several times.

> **If you see** no `Memory:` line, **it means** you asked `postgresql.service`. On Ubuntu that unit is an empty wrapper; the cluster runs as `postgresql@16-main`.
